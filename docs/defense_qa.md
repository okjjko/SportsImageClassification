---

## 🔴 第一层：必问核心题（几乎一定会被问到）

---

### Q1. 为什么选 EfficientNet-B0，不选 ResNet-50 / ViT / MobileNet？

**参考答案要点：**

- **EfficientNet 的优势**：使用复合缩放（compound scaling）同时调整深度、宽度和分辨率，在同等参数量下精度更高。B0 约 5.3M 参数，比 ResNet-50（~25M）小得多，训练和推理都更快。
- **对比 ResNet-50**：代码中预留了 `create_resnet50()` 作为备选。ResNet-50 参数量约为 B0 的 5 倍，在数据量较小（1.3 万张）时更容易过拟合。B0 在 ImageNet 上的 Top-1 准确率（77.1%）已优于 ResNet-50（76.1%），是更优的基线选择。
- **为什么不用更大的 B3/B7**：数据集规模有限，更大模型更容易过拟合。B0 作为轻量级起点足够，且在 4GB 显存的 GPU 上也能训练。
- **为什么不用 ViT**：ViT 需要大量数据才能发挥优势（通常需要 JFT-300M 或 ImageNet-21K 级别），小数据集上往往不如 CNN。

---

### Q2. 为什么用全网络微调而不是冻结骨干只训练分类头？

**参考答案要点：**

- **冻结 vs 微调的权衡**：冻结骨干适合数据集与预训练数据非常相似且数据量极小的场景。运动图片与 ImageNet 的通用物体有一定差异（更强调动态姿势、特定场地），冻结骨干可能无法学到这些域特定特征。
- **过拟合防护**：虽然全量微调有更大过拟合风险，但通过 Dropout（0.3 + 0.2）、数据增强（4 种）和较小的学习率（1e-4）进行正则化，有效控制了过拟合。
- **证据**：训练曲线显示验证集准确率持续上升并趋于稳定，没有出现明显的验证 loss 急剧上升，说明全量微调策略在这个数据量下是可行的。
- **如果数据更少**（如每类只有几十张），则会考虑冻结骨干 + 只训练分类头，或使用更激进的正则化。

---

### Q3. 数据增强那四项，每项的物理意义是什么？

**参考答案要点：**

| 增强方法 | 参数 | 物理意义 |
|---|---|---|
| `RandomResizedCrop(224, scale=(0.8, 1.0))` | 裁剪比例 80%~100% | 模拟不同拍摄距离和构图——运动照片中运动员可能占据画面不同比例 |
| `RandomHorizontalFlip(p=0.5)` | 50% 翻转 | 运动动作存在左右对称性（如左/右手投篮、左/右脚踢球），翻转可让模型学到方向无关的特征 |
| `RandomRotation(15)` | ±15° 旋转 | 模拟相机倾斜和不同拍摄角度。15° 是一个适中值，更大的角度可能改变运动的语义（如体操颠倒后就不是同一个动作了） |
| `ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2, hue=0.1)` | 亮度/对比度/饱和度 ±20%，色调 ±10% | 模拟不同光照条件（室内/室外、白天/夜晚）和不同相机白平衡设置。hue 设为 0.1 而非 0.2 是因为过大的色调偏移可能改变运动场地的特征色（如绿色草地变蓝色） |

---

### Q4. 学习率调度为什么选 StepLR 而不是 CosineAnnealing 或 ReduceLROnPlateau？

**参考答案要点：**

- **StepLR 的特点**：简单、可预测，每 5 个 epoch 学习率减半。在训练初期用较大学习率快速收敛，后期逐步减小精修权重。
- **对比 CosineAnnealing**：余弦退火在后期学习率趋近于零的速度更平滑，适合长训练（50+ epoch）。本项目只训练 15 个 epoch，StepLR 的阶梯式衰减足够。
- **对比 ReduceLROnPlateau**：基于验证 loss 自适应衰减更"智能"，但需要额外监控指标，且在短训练中可能导致学习率过早降低。
- **验证**：从训练曲线的 LR 子图可以看到学习率在第 5、10 epoch 阶梯下降，对应训练 loss 的明显下降拐点，说明策略是有效的。

## 🟡 第二层：深入追问（展示理解深度）

---

### Q5. 分类头设计 1280→512→100，中间层为什么是 512？Dropout 为什么是 0.3 和 0.2？

**参考答案要点：**

- **中间层维度 512**：EfficientNet-B0 输出 1280 维特征，直接映射到 100 类维度跨度太大。加入 512 维的中间层起到"瓶颈"作用，先压缩特征再分类，减少参数量（1280×100 = 128K vs 1280×512 + 512×100 ≈ 707K，但中间层引入了更多非线性表达能力）。
- **为什么不是 256 或 1024**：256 可能压缩过度丢失信息，1024 则参数过多增加过拟合风险。512 是一个经验性的平衡点。
- **Dropout 0.3 和 0.2**：第一个 Dropout 更大（0.3），因为直接接骨干网输出，特征维度高、冗余多；第二个较小（0.2），因为已经压缩到 512 维，过多丢弃会影响分类判断。两层差异化设置比统一值更合理。
- **诚实回答**：如果没做过消融实验，可以说"这些值参考了 EfficientNet 微调的常见实践，理想情况下应通过网格搜索或消融实验验证最优组合"。

### Q6. 训练集 13,493 张，验证/测试集各 500 张，这个划分合理吗？

**参考答案要点：**

- **当前划分比例**：约 93% / 3.5% / 3.5%，验证集和测试集偏小。
- **问题**：100 个类别各只有 5 张测试图片，某个类别全对或全错会带来 ±20% 的准确率波动，统计上不够稳定。
- **合理性论证**：数据集本身来自 Kaggle，划分是数据集作者提供的，项目直接沿用。训练集较大有利于模型学习。
- **改进方案**：
  - 可以从训练集中划出更多数据给验证/测试集（如 80/10/10）
  - 使用 K-fold 交叉验证获得更稳定的评估
  - 数据增强也可以应用于测试集（TTA — Test Time Augmentation）取多次预测的平均值

---

### Q7. 混淆矩阵里哪些类别最容易被搞混？怎么区分"模型能力不足"和"数据本身就难区分"？

**参考答案要点：**

- **常见混淆对**（需要查看实际 `error_analysis.txt`）：可能是视觉上相似的运动，如 `table tennis` vs `badminton`（球拍运动）、`surfing` vs `wakeboarding`（水上板类运动）。
- **判断依据**：
  - 如果人类也容易混淆（需要专业背景才能区分），说明类别本身边界模糊，不完全是模型的问题
  - 如果人类一眼就能区分但模型搞错，说明模型特征提取能力不足
  - 可以查看错误样本图片：图片质量差、角度不典型、遮挡等属于数据问题
- **改进方向**：对高混淆类别增加训练样本、使用难样本挖掘（Hard Example Mining）、引入注意力机制。

---

### Q8. Gradio 用了懒加载单例，为什么不在启动时就加载？

**参考答案要点：**

- **懒加载的优点**：启动速度快（不需要等待模型加载），适合开发调试时频繁重启。
- **懒加载的缺点**：第一次预测请求延迟高（需要加载模型）；模型文件损坏或缺失要等到用户上传图片后才能发现。
- **改进方案**：
  - 在 `create_interface()` 中主动调用一次 `_get_model()` 进行预热加载
  - 或者在 `interface.launch()` 之前加载，并在启动时打印模型状态信息
  - 添加健康检查接口，启动后自动验证模型可用性

## 🟢 第三层：扩展/拔高题（答得好加分）

---

### Q9. 如果要部署到手机端，你会怎么改？

**参考答案要点：**

1. **模型转换**：PyTorch → ONNX → TensorFlow Lite (Android) 或 Core ML (iOS)
2. **模型量化**：FP32 → INT8 量化，模型大小可减小 4 倍，推理速度提升 2-3 倍，精度损失通常 < 1%
3. **模型剪枝**：去除不重要的通道/层，进一步减小模型体积
4. **更轻量架构**：考虑 EfficientNet-Lite（专为移动端优化）或 MobileNetV3
5. **B0 的可行性**：~5.3M 参数在 FP16 下约 10MB，INT8 量化后约 2.5MB，现代手机完全能跑，实时推理可行

---

### Q10. 如果新增第 101 种运动类别，但只有 50 张图片，你怎么处理？

**参考答案要点：**

- **方案一：微调扩展**。在现有 100 类模型基础上，将分类头扩展为 101 类，冻结骨干网络，只用 50 张新图片训练新的分类头权重。风险是新类过拟合。
- **方案二：数据增强扩充**。对 50 张图片施加更强的数据增强（如 Mosaic、MixUp、CutMix），扩充到几百张。
- **方案三：Few-shot / 元学习**。使用 Prototypical Network 或 MAML 等方法，但实现复杂度高。
- **方案四：检索式方案**。不训练新类，而是用现有模型提取特征，用 KNN 在特征空间中做最近邻匹配。
- **推荐**：方案一（微调扩展）最实用，配合方案二（增强扩充）效果最好。

### Q11. 如果给代码补单元测试，优先测哪些模块？

**参考答案要点：**

1. **`predict.py`** — 优先级最高。测试 `predict_image()` 的输出格式（dict 列表）、top_k 参数、非 RGB 图片自动转换、空输入处理。
2. **`dataset.py`** — 测试数据增强输出尺寸是否正确、`get_dataloaders()` 返回的 batch 形状、类别名正确性。
3. **`model.py`** — 测试模型输出形状 `(batch, 100)`、`count_parameters()` 计数准确。
4. **`config.py`** — 测试路径拼接正确性、目录自动创建。
5. **集成测试** — 用一张测试图片走完 load_model → predict_image 全流程。

### Q12. 如果验证 loss 在第 8 个 epoch 开始上升（过拟合），你会怎么调？

**参考答案要点：**

按优先级排序：

1. **Early Stopping**：监控验证 loss，连续 N 个 epoch 不下降则提前终止
2. **加大正则化**：增大 Dropout（如 0.3→0.4），或加入权重衰减（weight_decay=1e-4）
3. **增强数据增强**：引入 MixUp / CutMix / Mosaic 等高级增强策略
4. **Label Smoothing**：将 CrossEntropyLoss 的标签从硬标签 (0/1) 改为软标签 (如 0.9/0.001)，防止过度自信
5. **减少模型容量**：使用更小的中间层（512→256）或换更小的模型
6. **冻结部分骨干层**：只微调后几层，降低模型自由度
