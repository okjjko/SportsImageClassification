## 1. 问题定义：图像分类

### 本项目要解决什么问题

给定一张运动场景的图片，判断它属于 100 种运动中的哪一种。这是一个**多分类问题**（Multi-class Classification），输入是一张图片，输出是一个类别标签。

### 形式化描述

- 输入：一张 RGB 图片（3 个颜色通道）
- 输出：100 个类别中概率最高的那个
- 本质：学习一个映射函数 f(图片) → 类别概率分布

### 与其他视觉任务的区别

| 任务 | 输出 | 示例 |
|------|------|------|
| **图像分类**（本项目） | 一个类别标签 | "这张图是篮球" |
| 目标检测 | 多个类别 + 位置框 | "左上角有一个人，右边有个篮球" |
| 图像分割 | 每个像素的类别 | "这些像素属于人，那些像素属于球场" |
| 图像生成 | 一张新图片 | 根据文字描述生成运动场景图 |

## 2. 技术路线选择：深度学习 vs 传统方法

### 传统机器学习方法

在深度学习流行之前（2012 年以前），图像分类使用的是手工设计特征 + 分类器的两阶段方法：

1. **手工提取特征**：SIFT（尺度不变特征变换）、HOG（方向梯度直方图）、颜色直方图等
2. **训练分类器**：SVM（支持向量机）、随机森林、KNN 等

**局限性**：手工特征只能捕捉浅层模式（边缘、纹理），无法学习高层语义（"这个姿势是高尔夫挥杆"），准确率天花板低。

### 深度学习方法

让神经网络自动从数据中学习特征，不需要人工设计。

| 维度 | 传统方法 | 深度学习 |
|------|---------|---------|
| 特征提取 | 人工设计，领域知识依赖 | 自动学习，端到端优化 |
| 准确率上限 | 低（ImageNet 上约 50%） | 高（ImageNet 上 >80%） |
| 数据需求 | 少（几百张即可） | 多（通常数千张以上） |
| 计算资源 | CPU 即可 | 通常需要 GPU |
| 代表方法 | SIFT + SVM | CNN（卷积神经网络） |

**本项目选择深度学习**：100 类运动分类是一个复杂任务，传统方法的准确率远不够用。

## 3. 深度学习框架：PyTorch vs TensorFlow

### 两个框架的来历

| 框架 | 开发者 | 首次发布 | 现状 |
|------|--------|---------|------|
| **PyTorch** | Meta（Facebook）AI 研究院 | 2016 年 | 学术界主流，论文复现首选 |
| **TensorFlow** | Google Brain | 2015 年 | 工业界广泛使用，但学术界份额下降 |

### 核心差异

| 维度 | PyTorch | TensorFlow / Keras |
|------|---------|-------------------|
| 计算图 | 动态图（Eager Mode），写代码即执行 | 静态图为主（TF 2.x 也支持动态但不自然） |
| 调试 | 原生 Python 调试，可用 print、pdb 断点 | 计算图封装重，错误信息难读 |
| 学术论文采用率 | >80%（2023 年顶会统计） | 下降趋势 |
| 预训练模型 | `torchvision.models` 丰富 | `tf.keras.applications` 也有 |
| 代码风格 | Pythonic，面向对象 | 声明式风格 |

**本项目选择 PyTorch**：课程任务书指定，且 PyTorch 是学术界主流，查阅资料和复现代码最方便。

## 4. 模型架构：EfficientNet-B0 vs ResNet-50 vs MobileNetV2

### 卷积神经网络（CNN）的发展历程

```
AlexNet (2012)          → 8 层，证明深度学习可行，ImageNet 冠军
    ↓
VGGNet (2014)           → 16-19 层，证明"更深=更好"，但参数 1.38 亿
    ↓
GoogLeNet/Inception (2014) → 引入多尺度卷积（1×1、3×3、5×5 并行）
    ↓
ResNet (2015)           → 引入残差连接，解决深层网络梯度消失，可训练 152 层
    ↓
MobileNet (2017)        → 深度可分离卷积，面向手机端，参数少但精度低
    ↓
SENet (2017)            → SE 注意力模块，让模型自动学习通道重要性
    ↓
EfficientNet (2019)     → 复合缩放策略，同时优化深度+宽度+分辨率
    ↓
ViT (2020)              → Vision Transformer，把 NLP 的 Transformer 用在图像上
```

### 三款候选模型对比

#### ResNet-50（何恺明等，微软研究院，2015）

- **核心创新**：残差连接（Skip Connection）
  - 普通 CNN：每层学习完整映射 H(x)
  - ResNet：每层学习残差 F(x) = H(x) - x，输出 = F(x) + x
  - 好处：梯度可以直接通过捷径传回浅层，训练更深网络不会梯度消失
- **参数量**：25.6M
- **ImageNet 精度**：76.1%
- **问题**：对于 100 类、每类 135 张图片的数据集，25.6M 参数太容易过拟合

#### MobileNetV2（Google，2017）

- **核心创新**：深度可分离卷积 + 倒残差结构
  - 标准卷积：一个 3×3 卷积核同时处理所有通道，参数多
  - 深度可分离卷积：先逐通道卷积（每个通道独立），再用 1×1 卷积混合信息，参数减少 8-9 倍
- **参数量**：3.4M
- **ImageNet 精度**：71.8%
- **问题**：为手机端优化，服务端训练不是最优，精度偏低

#### EfficientNet-B0（Tan & Le，Google Brain，2019）

- **核心创新**：复合缩放（Compound Scaling）
  - 之前的模型只调整一个维度（深度、宽度或分辨率）
  - EfficientNet 同时按比例调整三个维度：深度 × α^φ、宽度 × β^φ、分辨率 × γ^φ
  - 先用 NAS（神经架构搜索）找到最优基础网络 B0，再按比例放大得到 B1~B7
- **内部结构**：
  - **MBConv 模块**：Mobile Inverted Bottleneck，融合了深度可分离卷积（省参数）和倒残差结构
  - **SE 注意力**：Squeeze-and-Excitation 模块，自动学习"哪些通道重要"，对重要通道加权、不重要的抑制
  - **残差连接**：借鉴 ResNet，输入直接加到输出
- **参数量**：5.3M
- **ImageNet 精度**：77.1%

### 最终选择

| 模型 | 参数量 | 精度 | FLOPs | 结论 |
|------|--------|------|-------|------|
| ResNet-50 | 25.6M | 76.1% | 4.1G | 参数太多，易过拟合 |
| MobileNetV2 | 3.4M | 71.8% | 0.3G | 精度太低 |
| **EfficientNet-B0** | **5.3M** | **77.1%** | **0.4G** | **精度最高、参数最少、计算量最低** |

EfficientNet-B0 在三个维度上都是最优或接近最优，是"小而强"的最佳平衡点。

## 5. 训练策略：迁移学习与全网络微调

### 什么是迁移学习

用一个任务（如 ImageNet 1000 类分类）上学到的知识，来帮助解决另一个任务（100 类运动分类）。

**为什么有效**：CNN 的浅层学到的是通用视觉特征（边缘、纹理、颜色），这些特征对任何图片都有用。只有深层特征是任务特定的。所以可以复用浅层特征，只调整深层。

### 两种迁移学习策略

#### 策略 A：冻结骨干 + 仅训练分类头

```
骨干网络（ImageNet 预训练权重）  →  冻结（不更新）
                                        ↓
                              新分类头（随机初始化）  →  训练
```

- 冻结：设置 `requires_grad = False`，反向传播时不计算梯度
- 优点：训练快（只更新少量参数）、不容易过拟合
- 缺点：特征提取器无法适应新领域，精度天花板低

#### 策略 B：全网络微调（Fine-tuning）

```
骨干网络（ImageNet 预训练权重）  →  所有参数都更新（用小学习率）
                                        ↓
                              新分类头（随机初始化）  →  所有参数都更新
```

- 所有层的 `requires_grad = True`
- 使用很小的学习率（1e-4），避免大步修改破坏预训练特征
- 优点：所有层都能适应新任务，精度天花板高
- 缺点：训练慢一些，过拟合风险更高（需配合正则化）

### 本项目为什么选全网络微调

运动图片与 ImageNet 通用物体有明显的**域差异（Domain Gap）**：

- ImageNet 里的"篮球"是一个静止的球体
- 运动数据集里的"篮球"是人打篮球的场景，包含特定姿态、球场、装备
- 冻结骨干无法学习这些运动特有的视觉模式

配合 Dropout、数据增强、学习率衰减等正则化手段，可以控制过拟合风险。

## 6. 数据预处理与增强

### 为什么需要预处理

原始图片千姿百态：不同尺寸、不同光照、不同构图。模型需要统一的输入格式才能训练。

### 为什么需要数据增强

每类只有约 135 张训练图片，模型容易记住训练集的每张图片（过拟合）。通过对同一张图片施加随机变换，每次模型看到的都是不同的"版本"，相当于扩充了数据量。

### 训练集预处理流水线

| 步骤 | 操作 | 做了什么 | 为什么 |
|------|------|---------|--------|
| 1 | RandomResizedCrop(224, scale=(0.8, 1.0)) | 随机裁剪 80%~100% 区域，缩放到 224×224 | 模拟不同拍摄距离和构图 |
| 2 | RandomHorizontalFlip(p=0.5) | 50% 概率左右翻转 | 多数运动左右对称（左手/右手投篮是同一类） |
| 3 | RandomRotation(15) | 随机旋转 -15° ~ +15° | 手持拍摄常见小角度倾斜 |
| 4 | ColorJitter(0.2, 0.2, 0.2, 0.1) | 随机调整亮度、对比度、饱和度、色调 | 模拟晴天/阴天/室内灯光 |
| 5 | ToTensor() | PIL 图片 → 张量，像素 [0,255] → [0,1] | PyTorch 模型只接受张量输入 |
| 6 | Normalize(mean, std) | 用 ImageNet 均值标准差标准化 | 预训练模型期望输入与 ImageNet 一致 |

### 验证/测试集预处理

```
Resize(256) → CenterCrop(224) → ToTensor → Normalize
```

没有任何随机操作。Resize(256) 把短边缩到 256，CenterCrop(224) 从中心裁出 224×224。这样同一张图片每次处理结果完全相同，评估可复现。

### 为什么不做某些增强

| 不使用的操作 | 排除理由 |
|------------|---------|
| 垂直翻转 | 重力方向有语义（跳水向下、跳高向上），翻转后含义改变 |
| 大角度旋转 >30° | 体操倒立和站立是不同动作，大角度旋转破坏运动姿态 |
| RandomErasing | 可能擦掉球拍、球类等关键装备 |
| 高斯噪声 | 预训练模型未见过大量噪声，可能降低特征质量 |

### Normalize 的均值和标准差从哪来

```
mean = [0.485, 0.456, 0.406]   ← ImageNet 120 万张图片 R/G/B 通道的像素平均值
std  = [0.229, 0.224, 0.225]   ← ImageNet 120 万张图片 R/G/B 通道的像素标准差
```

公式：`output = (input - mean) / std`

效果：把像素值从 [0, 1] 转为以 0 为中心、标准差约 1 的分布。预训练权重是基于这个分布训练的，如果输入分布不匹配，模型性能会下降。

## 7. 自定义分类头设计

### 原始分类头 vs 自定义分类头

**EfficientNet-B0 原始分类头**（ImageNet 1000 类）：

```
1280 维特征 → Dropout(0.2) → Linear(1280, 1000) → 1000 类 logits
```

只有一层全连接，输出 1000 个类别的原始分数。

**本项目的自定义分类头**（100 类运动）：

```
1280 维特征 → Dropout(0.3) → Linear(1280, 512) → ReLU → Dropout(0.2) → Linear(512, 100) → 100 类 logits
```

### 为什么不直接用单层 Linear

| 方案 | 结构 | 参数量 | 特征变换 |
|------|------|--------|---------|
| 单层 | Linear(1280→100) | 128,100 | 直接映射，无中间过渡 |
| **两层** | Linear(1280→512) → ReLU → Linear(512→100) | 706,612 | 先降维过渡再分类 |

1280 维直接映射到 100 类，跨度太大。中间层 512 维提供过渡，让特征逐步收敛。ReLU 引入非线性，使模型能学到更复杂的决策边界。

### Dropout 的作用

训练时随机"关闭"一部分神经元：

- **Dropout(0.3)**：关闭 30% 的输入特征，防止模型依赖骨干输出的某些特定维度
- **Dropout(0.2)**：关闭 20% 的中间层神经元，防止中间层过拟合

评估时（`model.eval()`）Dropout 自动关闭，所有神经元都参与计算，输出更稳定。

## 8. 损失函数

### 什么是损失函数

衡量模型预测与真实标签的差距。训练的目标就是**最小化损失函数**。

### 本项目使用：交叉熵损失（CrossEntropyLoss）

PyTorch 的 `nn.CrossEntropyLoss` 内部做了两件事：
1. 对模型输出的 logits 做 Softmax 转为概率
2. 计算预测概率分布与真实标签之间的交叉熵

```
loss = -log(预测概率[真实类别])
```

- 如果模型对正确类别给出高概率（接近 1），loss 接近 0
- 如果模型对正确类别给出低概率（接近 0），loss 接近无穷大

### 为什么不用其他损失函数

| 损失函数 | 适用场景 | 为什么不用 |
|---------|---------|-----------|
| **交叉熵** | 多分类 | **本项目选用** |
| MSE（均方误差） | 回归问题 | 分类任务不适用 |
| Focal Loss | 类别极度不平衡 | 本项目类别分布相对均衡 |
| Triplet Loss | 度量学习/人脸识别 | 不是本项目的任务类型 |

## 9. 优化器与学习率调度

### 优化器：Adam vs SGD

#### SGD（随机梯度下降）

- 2012 年 AlexNet 就用的 SGD
- 沿着梯度的反方向走一步：`参数 = 参数 - lr × 梯度`
- 需要精心调节学习率、momentum 等超参数
- 理论泛化能力略优

#### Adam（Adaptive Moment Estimation）

- Kingma & Ba，2014 年提出
- 为每个参数自适应地调整学习率：
  - 维护梯度的**一阶矩估计**（动量，类似 SGD Momentum）
  - 维护梯度的**二阶矩估计**（自适应学习率，梯度大的参数走小步，梯度小的走大步）
- 默认参数（lr=0.001, β1=0.9, β2=0.999）对大多数任务已经够用

| 维度 | Adam | SGD + Momentum |
|------|------|---------------|
| 收敛速度 | 快 | 慢 |
| 调参难度 | 低 | 高 |
| 微调场景 | 首选 | 需要更多经验 |

**本项目选择 Adam**：微调场景收敛更快、更稳定，调参成本低。

### 学习率调度：StepLR

训练过程中动态调整学习率。本项目使用 **StepLR**（2015 年随 ResNet 论文流行）：

```python
scheduler = StepLR(optimizer, step_size=5, gamma=0.5)
```

每 5 个 epoch 学习率乘以 0.5：

```
Epoch  1~5:  lr = 1e-4      ← 前期大步学习
Epoch  6~10: lr = 5e-5      ← 中期减小步长
Epoch 11~15: lr = 2.5e-5    ← 后期精细微调
```

**为什么不一直用固定学习率**：后期模型已接近最优解，大步容易"越过"最优点来回震荡。减小学习率让模型在最优解附近精细调整。

### 其他学习率调度方法（未选用）

| 方法 | 原理 | 未选用理由 |
|------|------|-----------|
| CosineAnnealing | 学习率按余弦曲线从大到小 | 需要调 T_max 等参数，对短训练（15 epoch）效果差异不大 |
| OneCycleLR | 先增后减的单周期策略 | 更复杂，适合从头训练而非微调 |
| ReduceLROnPlateau | 验证指标不降时才减小学习率 | 需要额外设定 patience 等参数，增加复杂度 |

## 10. 训练超参数选择

### 各超参数及选择依据

| 超参数 | 值 | 为什么是这个值 |
|--------|-----|--------------|
| batch_size | 32 | 经验值。太小（如 8）→ 梯度噪声大，训练不稳定。太大（如 128）→ 泛化差，且显存可能不够。32 是常见甜点 |
| learning_rate | 1e-4 | 微调标准学习率。比从头训练的 1e-3 小 10 倍，防止大步修改破坏预训练权重 |
| epochs | 15 | 配合 StepLR 每 5 epoch 衰减，学习率经过 3 次衰减后足够收敛。过多 epoch 在小数据集上易过拟合 |
| num_workers | 0（Windows） | Windows 下多进程数据加载容易报 BrokenPipeError，设为 0 使用单进程 |

### batch_size 对训练的影响

```
batch_size 太小 (4~8):
  - 每步只用几张图片算梯度，梯度方向不稳定（噪声大）
  - 需要更多步才能收敛
  - 但正则化效果更强（噪声本身有正则化作用）

batch_size 适中 (16~64):
  - 梯度估计较准确
  - 训练稳定
  - 显存可承受

batch_size 太大 (128+):
  - 梯度非常准确，但每次更新"信号"太弱
  - 泛化性能可能下降
  - 显存可能溢出
```

## 11. 模型评估指标

### Top-1 准确率

预测概率最高的类别与真实标签一致的比例。这是最直观的指标。

```
Top-1 准确率 = 正确预测数 / 总样本数
```

### Top-3 准确率

真实标签出现在预测概率最高的前 3 个类别中的比例。

```
Top-3 准确率 = (真实标签在 Top-3 预测中的样本数) / 总样本数
```

为什么需要 Top-3：有些运动在视觉上确实很相似（如不同类型的滑雪），如果正确答案在 Top-3 中，说明模型至少"接近正确"，比完全搞错好得多。

### 精确率、召回率、F1

这三个指标按**每个类别**分别计算：

| 指标 | 公式 | 含义 |
|------|------|------|
| Precision（精确率） | TP / (TP + FP) | 预测为该类的样本中，真正是该类的比例（不误报） |
| Recall（召回率） | TP / (TP + FN) | 真实为该类的样本中，被正确预测的比例（不漏报） |
| F1 | 2 × P × R / (P + R) | 精确率和召回率的调和平均 |

其中 TP = 真正例，FP = 假正例，FN = 假反例。

### 混淆矩阵

一个 N×N 的矩阵（N=100），行表示真实类别，列表示预测类别。

- **对角线**：正确分类的样本数
- **非对角线**：被错误分类的样本数，(i, j) 位置表示"真实是 i 类但被预测为 j 类"的数量

通过分析非对角线元素，可以找出最容易混淆的类别对（如 snow boarding 和 giant slalom）。

## 12. 正则化策略

### 什么是正则化

防止模型过拟合（在训练集上表现好但测试集上差）的技术。过拟合的本质是模型记住了训练数据的细节而非学到通用规律。

### 本项目使用的正则化手段

| 手段 | 原理 | 本项目的使用 |
|------|------|------------|
| **Dropout** | 训练时随机丢弃部分神经元，迫使模型不依赖任何单个特征 | 分类头两层 Dropout（0.3 + 0.2） |
| **数据增强** | 对训练图片施加随机变换，每次看到不同版本 | 4 种增强操作（裁剪、翻转、旋转、色彩） |
| **学习率衰减** | 后期减小学习步长，避免在最优解附近震荡 | StepLR 每 5 epoch 减半 |
| **小学习率微调** | 不用大学习率，避免破坏预训练权重 | lr=1e-4 |
| **早停（隐式）** | 保存验证集上最佳的模型，即使后续 epoch 表现下降也保留最佳版本 | 每个 epoch 保存 best model |

### 各手段的来历

- **Dropout**：Srivastava et al., 2014，"Dropout: A Simple Way to Prevent Neural Networks from Overfitting"
- **数据增强**：深度学习的通用实践，最早可追溯到 2012 年 AlexNet（使用了裁剪和翻转）
- **学习率衰减**：伴随 SGD 出现的经典技巧，StepLR 是最简单的实现
- **迁移学习**：Yosinski et al., 2014，"How transferable are features in deep neural networks?"

## 13. Web 应用部署：Gradio

### 什么是 Gradio

一个 Python 库，用几行代码就能为机器学习模型创建 Web 界面。由 Abubakar Abid 等人于 2021 年创建（后成立 Gradio 公司，被 Hugging Face 收购）。

### Gradio vs Streamlit vs Flask

| 维度 | Gradio | Streamlit | Flask |
|------|--------|-----------|-------|
| 定位 | ML 模型演示 | 数据仪表盘 | 通用 Web 框架 |
| 代码量 | 极少（3~5 行） | 中等 | 较多（需写 HTML） |
| 图像上传 | `gr.Image` 内置 | `st.file_uploader` | 需自行实现 |
| 学习曲线 | 极低 | 低 | 中等 |
| 适合场景 | 模型推理演示 | 数据分析展示 | 完整 Web 应用 |

**本项目选择 Gradio**：任务书推荐，且只需要"上传图片→展示预测结果"，Gradio 最简洁。

### 本项目的 Gradio 工作流

```
用户上传图片（浏览器）
    ↓
Python 接收 PIL Image 对象
    ↓
应用与验证集相同的预处理（Resize → CenterCrop → Normalize）
    ↓
送入模型前向传播
    ↓
Softmax 转为概率
    ↓
返回 Top-3 类别 + 置信度 → Gradio 自动渲染为标签条形图
```
